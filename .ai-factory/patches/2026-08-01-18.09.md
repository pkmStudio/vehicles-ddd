# Root architecture document drift after AI Factory architecture update

**Date:** 2026-08-01 18:09
**Files:** `ARCHITECTURE.md`
**Severity:** low

## Problem

`$aif-verify` reported context drift: the root `ARCHITECTURE.md` still listed already fixed
architecture debts for `VehicleCrmController`, `RequestLocalImportCommand`, and
`WiperSpecificationService`, while `.ai-factory/ARCHITECTURE.md` had already been updated.

This made the two architecture references contradict each other.

## Root Cause

The AI Factory architecture artifact was updated after implementation, but the root human-facing
architecture document was not synchronized in the same pass. The root document therefore retained
historical debt entries that no longer matched the current code.

## Solution

Updated `ARCHITECTURE.md` to match `.ai-factory/ARCHITECTURE.md`:

- Removed the three stale debt entries that were already implemented.
- Kept the remaining style cleanup and deferred MoySklad debt.
- Added the queued Excel import serialization rule.
- Added the queued Excel import placement/testing guidance to the "where to put new code" table.

No runtime logging was added because this is a documentation-only fix with no executable code path.

## Prevention

- When `$aif-architecture` updates `.ai-factory/ARCHITECTURE.md`, check whether the root
  `ARCHITECTURE.md` has overlapping sections that also need synchronization.
- During `$aif-verify`, treat stale architecture debt lists as context drift even when code and tests
  pass.
- Keep `.ai-factory/ARCHITECTURE.md` as the workflow source for AI skills and root `ARCHITECTURE.md`
  as the human-facing detailed reference, but avoid contradictory debt lists.

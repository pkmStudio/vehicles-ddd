# Nomenclature REST preload and wiper optional fields

**Date:** 2026-08-04 19:24
**Files:** `NomenclatureCrmController.php`, `NomenclatureCrmReadRepository.php`, `NomenclatureRestEditForm.php`, `NomenclaturesRestTable.php`, `WiperDetailsData.php`, `WiperDetailsBuilder.php`
**Severity:** medium

## Problem

Filament REST forms for Warehouse nomenclature did not preload Brand and Type options. The REST
option endpoints were also capped at 50 records, so enabling preload only in the UI would still
leave larger dictionaries incomplete. Separately, the Nomenclature `wiper` details builder treated
front and rear wiper-specific fields as always required.

## Root Cause

The first REST implementation copied the search-oriented option limit from compact lookup endpoints
into dictionary endpoints. For Templates, the typed Nomenclature Wiper DTO mirrored all columns as
non-nullable and the builder used `pullRequired*` methods even for fields that the original
dan-center Filament template did not mark as required.

## Solution

Raised the Nomenclature option endpoint cap to 1000 for Brand/Type preload and enabled Filament
`preload()` for REST Brand/Type selects and filters. Changed Nomenclature Wiper length fields to
nullable and switched front/rear adapter parsing from required multi-selects to optional
multi-selects.

## Prevention

When moving Filament resources to REST-backed screens, distinguish search limits from preload
dictionary limits. When porting Template DTOs from legacy Filament templates, copy the per-field
required rules from the original template instead of assuming every constructor field is required.
